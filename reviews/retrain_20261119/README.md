# Black与Wolf从零训练

本目录是JC上两种机器人的唯一训练源码仓库。运行环境统一放在相邻的`../.venv`，本目录的`.venv`指向它。旧权重、重复项目、交付压缩包和训练日志不作为本框架依赖。

## 训练结构

每种机器人内部，教师与学生共用同一个动作头和HIM。教师从相机可见几何提取地形特征，学生从同次曝光的深度图和视觉记忆预测同一特征。完整特权状态供教师critic训练使用。两种机器人的动作语义不同，各有自己的参数。

|项目|Black|Wolf|
|---|---|---|
|本体历史|5×45|6×53|
|共享动作头输入|96|104|
|输出|12个腿关节位置动作|12个腿关节位置动作+4个轮速动作|
|HIM输出|下一帧速度3维+状态特征16维|下一帧速度3维+状态特征16维|
|可见地形特征|32维|32维|
|学生更新对象|CNN、GRU|CNN、GRU|

顺序为基础平地→低速纯轴起停→综合六种地形→专项分支。专项包括楼梯、平台、高墙、坡道、断桥、梅花桩。综合地形和专项保留平地样本。新训练线从随机初始化开始，后续阶段继承本条新训练线的合格教师。

## 入口

在本目录执行：

```bash
uv run --no-sync --offline python -m black.run
uv run --no-sync --offline python -m wolf.run
make check
```

默认入口只显示计划。实际执行需要显式模式和新的输出目录。具体命令、课程验收和恢复语义见[Black说明](docs/black.md)和[Wolf说明](docs/wolf.md)。训练产物统一放`runs/`，不进Git。

## 保留内容

- `black/`、`wolf/`：模型、训练、评估与对应测试。Black另有模型导出；Wolf导出和部署适配器待实现。
- `support/black/`：两种机器人复用的相机、几何和必要课程实现。
- `src/mjlab/`：实际使用的仿真运行时、机器人资产及环境配置。
- `docs/history.md`、`provenance.json`：提炼的经验、故障边界和来源指纹。
- `evidence/`：本次检查的紧凑结果，不放完整轨迹或旧权重。

## Git与存储

每完成一项可运行修改就提交源码和相应说明。阶段存档只保留恢复需要的最新点、验证表现最佳点和验收引用点；删除被评估引用的存档前同步处理该评估索引。用Git记录代码变化，避免复制整棵项目做备份。

Wolf模型资产来自团队资料。这个完整仓库先用本地Git管理；公开仓库的架构说明和代码审查不应包含未经授权的团队模型资产。Git历史也占空间，不提交大权重、缓存或重复压缩包。

短GPU检查只验证接口和有限窗口稳定性。旧NaN根因、4096环境长期稳定性、实际任务能力、Wolf相机安装和实机闭环仍需分别取得证据。
